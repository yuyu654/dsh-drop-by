# 陪伴 · dsh-drop-by

**让你的 DS 主动来找你，也有自己的新鲜事想分享。**

一个为 DeepSeek Harness（DSH）打造的主动陪伴插件。

沿用你设定的人设，结合最近聊天、记忆与作息，挑合适的时机来聊两句。TA 可以自己查资料、浏览网页、探索感兴趣的视频，在研究与休闲之间切换，把新的发现和手头的进展带回来。你也可以在 QQ 或抖音里给 TA 派个任务，完成后直接收到结果。

**主动的频率、探索的方向、需要安静的时间，都由你决定。**

[快速开始](#quick-start) · [自主探索](#exploration) · [鱼鱼状态与手机接入](#fish-condition) · [常见问题](#faq) · [下载与更新](https://github.com/yuyu654/dsh-drop-by/releases) · [反馈问题](https://github.com/yuyu654/dsh-drop-by/issues)

> 当前为早期测试版本。QQ 本机测试组合为 `dsh-plugin-qq-bridge` + `snowluma`，其他 QQ 接入方式尚未充分验证。网页、视频、记忆、情绪和手机感知可按需配置；具体依赖与兼容范围见下文。

## 你会体验到什么

### TA 会主动来找你，也懂得留一点空间

接着上次的话题聊，分享刚发现的内容，或随口问候一句。开启模型判断后，TA 会结合当下处境决定是否开口；你忙的时候少打扰，经常没有回应的话题也会减少出现。

支持近期话题、探索分享、项目问候、课表与考试、作息照应等主动场景。各种由头可以单独开关，日常消息受间隔、免打扰和每日上限约束。

### TA 有自己正在琢磨的事

根据人设与兴趣，在持续研究和休闲浏览之间切换。可以指定想探索的问题，也可以让 TA 自己挑选方向。研究和休闲分别保存进展，有值得分享的发现时，再带回来与你聊。

兴趣可以很具体：一个技术问题、一部作品、某类游戏或一个常看的网站。能读到多少内容，就基于多少内容讨论；探索记录会区分标题摘要、网页正文、视频画面或口播等证据来源。

### 在手机上聊，也能把事情往前推进

QQ、抖音私信任选一个作为主聊天入口，共用 DSH 会话。你可以直接说：

- “帮我查一下反时限过流保护的开源实现。”
- “继续推进刚才那个探索。”
- “整理一下昨天的探索笔记。”
- 在 TA 提出换源请求后回复：“可以，去知乎找找看。”

这些是指令示例，实际接单口吻由人设与模型生成。支持的任务会在后台执行，完成后经当前主通道回传结果；没找到资料或执行失败时也会反馈，不必等下一次日常主动消息。

### 对话有前情，也有当下的心情

连发消息会先合并，热聊时可以顺着当前话题补一句。会话上下文接近设定阈值时，可提前准备新会话，在切换后带上最近的对话继续聊。

可搭配长期记忆与情绪画像插件，让回复参考以前的事情，并延续近期聊天和探索产生的心情底色。心情影响表达，不单独作为增加主动消息的理由。

### 按你的生活节奏来

可选接入课表、考试安排、Windows 桌面状态，以及配套安卓应用「鱼鱼状态」同步的作息、运动与手机使用信息。你可以选择哪些信息参与陪伴，也可以只使用聊天与探索功能。

默认不要求你一直坐在电脑前。只要运行 DSH 的电脑保持开机、联网且宿主正常运行，你离开桌面后仍可通过手机聊天。

## 快速开始

### 1. 安装陪伴插件

在 DSH 插件市场搜索 `dsh-drop-by`，或通过 GitHub 地址安装：

```text
https://github.com/yuyu654/dsh-drop-by
```

使用 DSH CLI 时，把插件安装到你实际使用的 profile。例如桌面 profile：

```bash
dsh plugin --profile desktop add github:yuyu654/dsh-drop-by
```

使用其他 profile 时，将 `desktop` 换成对应名称。安装后重启 DSH，在设置中打开「陪伴」。宿主版本要求以仓库 [package.json](https://github.com/yuyu654/dsh-drop-by/blob/main/package.json) 为准。

### 2. 先接通一个聊天入口

首次配置建议先完成 QQ 桥的登录、配对和 DSH 会话绑定，在「陪伴 → 聊天接口」选择 QQ，并填写目标联系人。

计划以抖音为主入口时，也请先完成这个绑定步骤。本版通过已有 QQ 私聊绑定找到要共用的 DSH 会话，再由陪伴接管抖音收发。具体操作见 [聊天入口配置](#chat-channels)。

### 3. 配置人设与主动节奏

- 已使用 `dsh-agent-md` 时，陪伴可读取其全局人格；也可在本插件目录的 `persona.md` 中填写人设。
- 在「决定 TA 粘不粘人」中设置每日主动消息上限与最短间隔。
- 按自己的作息设置「全局静默」和「忙碌时段」。忙碌时段主要限制主动找话题，适合上课、上班或需要专注的时间。
- 希望 TA 自己判断是否值得开口时，开启「让模型自己决定说不说」。想允许没有具体事件的轻松招呼，再开启「没什么事也可以说一句」。

### 4. 试跑，再开启实际发送

默认开启「演练模式」，关闭「允许真的发送」。先查看设置页状态与试跑结果，确认联系人、口吻和触发理由符合预期。

准备开始使用时，关闭「演练模式」，打开「允许真的发送」，并确认当前通道的发送开关已开启。没有合适话题或仍在冷却期时，试跑可能跳过，这是正常结果。

### 5. 按需增加探索、记忆或手机感知

这些能力都可以后续再接：

| 想获得的体验 | 接下来配置 |
|---|---|
| TA 自己查资料、找新话题 | 自主探索、网页搜索、主动分享 |
| TA 理解视频画面 | `dsh-video-storyboard` 与支持图片的模型 |
| 跨会话参考长期记忆 | `dsh-fish-memory` |
| 延续聊天中的心情 | `emotion-state-portrait` |
| 参考睡眠、步数和手机使用情况 | 「鱼鱼状态」与邮箱收取 |

## QQ 与抖音主聊天入口

### QQ

1. 安装并启用 `dsh-plugin-qq-bridge`，按其说明完成登录或配对。
2. 将目标联系人的私聊绑定到希望持续使用的 DSH 会话。
3. 在陪伴中填写同一联系人的 QQ 标识，主聊天接口选择「QQ」。
4. 用一条普通消息确认桥接回复正常，再试用陪伴的主动分享或私聊任务。

共用会话的切换流程要求该联系人有一条启用的权威私聊绑定；同一联系人绑定多条会话时，请先在 QQ 桥面板整理绑定。

### 抖音私信

1. 安装 `dsh-douyin-scroll`，按其说明完成登录和运行环境配置，并与目标用户建立私信会话。
2. 保留已配置好的 QQ 桥及其会话绑定。
3. 在陪伴设置页选择主聊天接口「抖音私信」。联系人 `sec_uid` 和昵称留空时会尝试从抖音插件获取，也可手动填写。`sec_uid` 不是个人主页上显示的抖音号。
4. 通过陪伴设置页完成切换。插件会关闭原抖音「聊天盯梢」，协调停用对应 QQ 绑定，并接管抖音私信收发。
5. 若面板提示需要重启，重启 DSH 后再开始聊天。切回 QQ 时，原抖音聊天盯梢保持关闭。

陪伴使用抖音插件提供的读写脚本，不修改第三方插件源码。切换会协调第三方插件的配置与绑定状态；使用陪伴接管期间，请保持原抖音聊天盯梢关闭，避免重复回复。

抖音私信轮询默认 **30 秒**，可在设置页调整为 **10–300 秒**。抖音 IM 接口会检测请求模式，密集轮询或探测可能触发 `too many requests` 限流，因此最低为 10 秒。读取失败时会退避重试，抖音的响应速度也受轮询与浏览器发送耗时影响。

### 两个入口的差异

| 项目 | QQ | 抖音私信 |
|---|---|---|
| 消息接收 | 由 QQ 桥实时接入 | 由陪伴定时轮询 |
| 主通道 | 二选一 | 二选一 |
| DSH 对话 | 使用已绑定会话 | 接入同一共用会话 |
| 附件 | 取决于 QQ 桥和模型能力 | 当前支持文字与视频卡片；其他附件可能显示为占位文本 |
| 主动消息排版 | 可分成短句发送 | 通常合并成一条，减少发送等待 |
| 群聊 | QQ 桥本身可支持群聊；陪伴任务识别面向配置联系人的私聊 | 当前面向单个配置联系人的私信 |

主通道切换不等于把两个平台的所有历史消息自动导入；连续性来自接入同一条 DSH 会话及已配置的记忆来源。

### 长会话接力

默认在绑定会话完成一轮后检查上下文占用率，达到 **80%** 时预建同工作区的新会话，并通过当前主通道提醒。旧会话仍可继续使用。

你可以按面板提示重新绑定，或在开启预备绑定时重启 DSH 切换。新会话收到第一条消息时，会读取旧会话截至切换时的最近对话，作为前情一次性带入；读取失败时使用预存快照。

阈值可设为 **10%–95%**，携带消息数可设为 **0–50 条**，默认 10 条。用户和助手的一条消息各计一条。建议搭配 `dsh-fish-memory` 的工作区共用记忆，保留更长期的背景。

## 自主探索：研究与休闲

### 开启方式

在「自主探索」中开启「自动自主探索」，再按需打开「探索时搜索网页」「探索时找视频」和「让探索进展参与主动分享」。这些是独立选项：保存了探索进展，不代表一定会立即发消息。

可先点击「试跑一轮（不发送）」查看选题、实际使用的工具与保存结果。

### 怎么决定探索什么

| 设置 | 作用 |
|---|---|
| 人设 | 提供长期的性格、兴趣和表达方式 |
| 最近对什么好奇 | 补充近期关注的主题、作品或网站，研究与休闲都参考；留空时按人设选题 |
| 近一轮探索主题 | 给下一轮指定具体题目；完成有效轮次后清空，恢复平时的选择 |
| 每几轮安排一次休闲 | 默认 3；设为 1 时每轮安排休闲，设为 0 时关闭定期休闲轮 |

例如，可以在「最近对什么好奇」里写：

```text
最近想了解独立游戏的关卡设计，也关注某部漫画的公开更新消息。
研究时看看开发者访谈，休闲时找有意思的评论或视频，有新发现再分享。
```

研究题本身也可以是娱乐兴趣。休闲轮允许只留下真实印象或分享候选，无须每轮产出研究结论。

### 网页与视频怎么使用

- **网页**：优先调用 `dsh-free-search`，必要时回退到宿主 `web_search`，再用 `web_fetch` 读取正文。单轮限制工具使用量，最多读取两页正文。
- **视频**：每轮最多处理一条。画面理解需要 `dsh-video-storyboard` 和支持图片的模型；字幕或口播可作为文字依据，只有标题时会记录这一限制。
- **进展**：保存研究与休闲的主题、收获、卡点和后续方向，之后可继续推进或参与聊天。
- **分享**：探索结果先成为候选，再经过主动消息的时段、间隔和额度判断。

网页探索目前读取公开资料，不继承个人浏览器登录态。追小说、追漫画可以先用于关注公开更新、介绍、访谈与评论；需要登录的正文或付费内容，不能保证自动读取。遇到这类页面，可在 DSH 会话中处理登录，或把可读取的正文交给 TA，登录本身不会自动让后台 `web_fetch` 获得权限。

### 节奏与费用

自动探索默认关闭，开启后默认间隔 **180 分钟**；研究与休闲比例、工具超时和进展保留时间均可调整。静默和忙碌时段会暂停自动探索。

可选「只在谷时自动探索」，按插件预设的北京时间与日历规则安排自动轮次；手动试跑不受该选项限制。实际费用取决于所用模型与服务商，不能把调度开关视为所有供应商都享有折扣的保证。

探索、意图判断、情绪更新和主动发言可能调用模型并产生费用。可以从较长探索间隔开始，按实际使用情况调整。

## 人格、记忆与心情

### 人格

优先读取 `dsh-agent-md` 提供的全局人格，可按设置加入项目人格；没有对应配置时使用插件目录的 `persona.md`，再退回内置简短口吻。

专属称呼、表达偏好与不想出现的口头禅，可以写在人设或 `local-style.json` 中。示例格式见 [local-style.example.json](https://github.com/yuyu654/dsh-drop-by/blob/main/local-style.example.json)。

### 长期记忆

可读取 `dsh-fish-memory` 的会话记忆与工作区记忆，选择需要参考的范围。设置页也支持将选中的旧会话记忆并入工作区：先预览，确认后写入，并提供备份与恢复。

日常读取记忆与手动合并是两个操作；长期记忆也不同于会话接力时携带的最近几条原始对话。

### 心情

「探索心情」可记录一轮探索带来的短暂感受；「延续聊天的心情（情绪插件）」需要安装 `emotion-state-portrait`，用于参考近期私聊与探索形成的情绪基调。

当前心情主要影响说话口吻，保留时长可调。它不等于完整的精力模拟，也不会仅因用户暂时没回消息就自动生气或增加催问。

## 配套安卓应用：鱼鱼状态

**把手机上已经有的生活信息，带进日常陪伴。**

「鱼鱼状态」（FishCondition）从健康应用界面读取睡眠、步数等信息，整理成摘要，通过你配置的邮箱发送。电脑端陪伴插件再用 IMAP 取回，作为作息照应与聊天背景。

```text
手机健康应用 / 系统使用时间
          ↓ 本机采集与解析
      鱼鱼状态 App
          ↓ SMTP 摘要邮件
       你的收件邮箱
          ↓ IMAP 读取
  dsh-drop-by 判断与生成内容
          ↓
     当前 QQ / 抖音入口
```

手机数据是可选能力，不安装 App 也可以使用聊天、主动分享和自主探索。

### 下载与适配范围

- [下载 FishCondition v0.1.2 APK](https://github.com/yuyu654/dsh-drop-by/releases/download/v0.1.0/FishCondition.apk) · [查看发布说明](https://github.com/yuyu654/dsh-drop-by/releases/tag/v0.1.0)
- 本节对应 **App v0.1.2，versionCode 13**；仓库发布标签与 App 版本号独立。
- APK 声明最低 Android 5.0（API 21），**压力页截图识别与手动诊断截图需要 Android 11 或以上**。建议使用 Android 11+；声明可安装不代表所有旧系统均已验证。
- 当前健康界面解析主要适配 **华为运动健康**，默认目标包名 `com.huawei.health`。换成其他健康应用，仅修改包名不代表解析规则也能适配。

### 可以采集什么

| 信息 | 来源与条件 |
|---|---|
| 起床时间、睡眠时长、步数、压力、心率、血氧 | 健康应用当前显示的文字；数据需要先同步到健康应用 |
| 睡眠详情 | 开启详情采集后读取睡眠页，包含能识别到的夜间睡眠、深睡、浅睡、快速眼动等 |
| 入睡时间 | 仅当页面暴露了可识别文字时读取；自绘图表没有文字时可能显示「未读到」 |
| 压力范围 | 开启压力详情；自绘压力页通过本机内存截图识别，需要 Android 11+ |
| 手机使用时间 | 另行授予「使用情况访问」后，读取系统统计；邮件可附带总时长及主要应用摘要 |

能读取多少取决于页面实际提供的数据。未读到的字段会保留缺失状态，不保证每次数据齐全。

### 手机端第一次配置

**1. 开启无障碍服务**

主页 →「系统权限辅助」→「打开无障碍设置」，找到「鱼鱼状态」并启用。授权后通过系统最近任务切回应用，查看顶部三个状态胶囊：无障碍、服务、保活。

红色状态可点击查看或跳转处理；正常运行时应显示已开或运行中。

**2. 检查后台运行条件**

主页 →「系统权限辅助」→「打开应用系统设置」。主动拉起需要系统允许后台弹出界面；若后台容易被清理，再按手机系统设置自启动、电池不限制或最近任务锁定。

允许通知，并按需点击「重新挂起前台保活」。不同手机的权限名称和位置可能不同。

**3. 配置发送邮箱**

主页 →「数据推送与详情」→「邮箱发送配置」，填写：

- 发件邮箱：完整邮箱地址。
- SMTP 授权码或应用专用密码：按邮箱服务商要求获取，不填写 QQ 登录密码。
- 收件邮箱：留空时发给自己；也可使用单独的收件邮箱。

App 当前按邮箱域名选择服务器，使用 SMTP 465/TLS 和账号授权码登录。其他邮箱是否可用取决于其实际端口与认证要求，不能仅凭域名自动识别就认为已经支持。

没有配置邮箱时，仍可在本机查看采集结果，但电脑端不会收到新数据。

**4. 选择采集方式**

主页 →「采集与目标配置」→「界面抓取方式」：

| 模式 | 实际行为 |
|---|---|
| 被动采集，默认 | 你自己打开健康应用时读取已显示内容，不自动拉起、滑屏或点击 |
| 主动拉起 | 满足桌面停留和间隔条件后，打开健康应用、翻页采集，再返回桌面 |
| 关闭 | 停止自动采集和每日定时采集，手动测试入口仍可使用 |

被动采集默认最短间隔 **10 分钟**；主动拉起默认桌面停留 **5 秒**、最短间隔 **180 分钟**。这些设置在 App 中调整，与电脑端读取邮箱的间隔分开。

**5. 完成一次实际采集**

被动模式下，先打开华为运动健康，等待首页数据同步并停留片刻。如开启了详情采集，再进入睡眠页或压力页停留，给读取和识别留出时间。

也可以在「辅助工具与测试」中点击「立即主动拉起一次」。手动主动测试会操作页面，测试期间等待其完成。

回到 App 查看结果和「查看流水」，再检查收件邮箱是否收到主题以 `FISH` 开头的邮件。看到邮件表示手机到邮箱这一段已通，接下来还需配置电脑收取。

### 电脑端接收手机数据

1. 打开 DSH「陪伴」，在「数据从哪来」中启用「手机数据」和「读邮箱」。
2. 在邮箱配置处填写**收件邮箱**及该邮箱的 IMAP 授权码。若手机从 A 发往 B，电脑应读取 B；发给自己时两端可以是同一邮箱。
3. 确保收件邮箱已开放 IMAP。服务器留空会按域名推断，无法识别时手动填写服务商提供的 IMAP 地址。
4. 设置允许读取时段和读取间隔，默认 **30 分钟**。静默时段会影响自动收取。
5. 查看插件状态或邮件读取日志，确认出现新的手机数据。排查时可使用下文的手动收取命令。

手机发出邮件后，电脑端要等下一次收取才会更新，因此这条链路不是实时传感。插件会记录邮件时间并限制旧数据的使用，避免拿过期摘要当作刚发生的情况。

### 睡眠、压力与使用时间

在「数据推送与详情 → 睡眠与压力详情」中分别启用需要的项目。默认不启用深度详情采集。

被动模式下，由你自己打开对应页面；主动模式下，App 会尝试进入详情。首页与详情会尽量合并后发信，详情不完整时可能等待一段时间，或先发送已经取得的部分。

- 同一健康日的详情通常只自动采集一次；需要重采时使用「重置今日标记」。
- 压力范围识别失败后，可能进入 7 天的自动重试避让；重置标记可解除。
- 「立即采一次详情」用于当前页面的就地读取。
- 「辅助工具与测试 → 手机使用时间与详情」可查看今天、昨天、最近 7 天的应用使用统计。首次使用按提示授予系统「使用情况访问」权限。

### 每日自动采集

默认开启，时间为 **07:30**，可在「每日自动采集」中修改或关闭。

- **被动模式**：到点后等待你打开健康应用，再读取当前页面，不自动抢占界面。
- **主动模式**：到点后等待亮屏、解锁，并在满足运行条件后尝试主动采集。
- **关闭采集模式**：每日自动采集也暂停。

每日采集与详情的健康日标记是不同机制。手环同步较慢时，可以把每日时间设在通常完成同步之后。

### 手机端排障

先看主页的三个状态胶囊，再看「查看流水」。原文和截图诊断位于「设置」页。

| 现象 | 优先检查 |
|---|---|
| 无障碍显示关闭、服务未运行 | 重新授权并切回 App；检查系统是否限制后台运行 |
| 主动拉起没反应 | 是否选择主动模式、达到桌面停留与间隔条件，以及是否允许后台弹出界面 |
| 读到文字但字段显示未读到 | 健康应用页面或文案可能改变；使用原文诊断定位 |
| 页面节点和文字都是空的 | 可能是自绘界面，无障碍无法取得文字；压力详情需走截图识别 |
| 压力范围识别失败 | Android 版本、截图能力、页面是否稳定，以及是否处于重试避让期 |
| 本机有结果，邮箱没有邮件 | SMTP 配置、授权码、网络和采集流水中的发信结果 |
| 邮箱有邮件，DSH 没有数据 | 电脑是否读取了正确收件箱、IMAP 是否启用、是否处于静默或收取间隔内 |
| 邮件没有手机使用时间 | 是否授予「使用情况访问」权限 |
| 升级后压力截图持续失败 | 在系统无障碍中关闭「鱼鱼状态」再开启，然后重新测试 |

安装同签名的新 APK 通常会保留本地配置。卸载会清除应用私有数据，换机需要重新配置；手动保存到相册的诊断截图请自行管理。

<a id="compatibility"></a>

## 兼容性与功能边界

- **需要 DSH 正在运行**：插件依托宿主与模型执行。电脑关机、休眠或宿主退出后，后台陪伴也会停止。
- **桌面感知主要适配 Windows**：键鼠空闲、前台窗口及系统 OCR 使用 Windows 能力；浏览器标签读取需要可连接的 Edge 调试端口。其他系统不能直接获得同等桌面感知能力。
- **QQ 与抖音能力有差异**：本版主通道二选一，抖音使用轮询，附件处理范围较窄；具体见聊天入口对照表。
- **网页读取限于工具实际能访问的内容**：不自动继承个人登录态，不保证读到登录后或付费正文。
- **视频看图需要模型支持**：仅安装分镜插件不能让纯文本模型直接看图；文字转写与标题摘要的证据范围不同。
- **手机适配受页面与系统影响**：主要针对华为运动健康，数据同步、页面改版、ROM 后台策略都会影响结果。
- **私聊任务有明确范围**：目前支持公开资料搜索、推进探索、整理探索笔记与陪伴插件快速自检；不是任意项目代码执行入口。
- **自然表达仍取决于模型与人设**：插件提供上下文、话题约束和重复检查，实际语气需要结合所用模型调整。

<a id="faq"></a>

## 常见问题

### 装好了，为什么一直不主动说话？

先检查演练模式、发送总开关、主通道联系人和绑定，再看是否命中静默、忙碌、每日上限或最短间隔。自动探索、探索分享、随口招呼等功能默认并非全部开启。

设置页的试跑结果和日志会说明跳过原因。试跑没有发言，不一定代表插件故障。

### 我离开电脑了，还能在手机上聊吗？

可以。默认关闭「只在电脑前才主动开口」，人的离开或锁屏不会单独阻止主动消息；但运行 DSH 的电脑仍需保持可执行任务的状态。

### 为什么探索几秒就结束，或者没有搜网页？

探索按本轮实际内容与工具调用完成，没有规定必须持续十分钟。检查是否开启网页或视频探索、宿主是否发现对应工具，以及本轮是否选择了外部资料。判断依据应是实际工具记录、证据与保存进展，不能只看耗时。

### 为什么探索结束了，没有马上分享？

探索进展会先保存。开启「让探索进展参与主动分享」后，它才成为主动消息候选，仍要满足适合开口的条件。你明确派发的私聊任务，则使用任务完成回传流程。

### 为什么回复“好”没有启动任务？

普通聊天中的“好”不会自动派活。只有前面有仍有效的具体待确认动作，或本条消息被识别为支持的主动指令，才会进入执行流程。确认时也可以附带关键词或搜索站点建议。

### 静默或关闭陪伴后，QQ 为什么还能回复？

陪伴的日常主动逻辑与 QQ 桥普通聊天是不同入口。关闭陪伴不等于停用第三方 QQ 桥；要完全停止对应私聊回复，需要同时检查桥接插件的绑定与回复设置。

### 需要同时把所有配套插件都装上吗？

按所需能力安装即可。先接通聊天，再逐步增加探索、记忆、情绪或手机感知，排查也更容易。

<a id="data"></a>

## 数据流向与本地文件

### 手机侧

- 健康数据主要在手机本机解析，邮件发送的是提取摘要，不附带完整页面原文或图片。
- 开启使用情况访问后，摘要可能包含手机使用总时长和主要应用名称。
- 自绘压力页的自动截图仅用于本机内存识别，不保存图片；设置页手动点击诊断截图时，会将图片保存至本机相册 `Pictures/FishCondition/`。
- 采集原文与诊断日志保存在手机本地，可从 App 设置页查看或清理。邮箱授权码保存在应用私有配置中。

### 电脑与外部服务

- 邮件经你配置的邮箱服务商传输、保存，电脑端通过 IMAP 读取。TLS 连接保护传输过程，不等于邮件内容端到端加密。
- 启用相关来源后，聊天、记忆、状态摘要等可能作为提示词交给你在 DSH 中配置的模型服务。网页搜索与视频能力也会访问相应服务。
- 电脑端可能保存配置、近期状态、探索记录、邮件摘要与运行日志。不要将“本地保存”理解为全部处理都不联网。
- 插件通过配置的聊天入口发送消息，不以自动关注、点赞或刷量作为陪伴功能。

以下文件与目录已由仓库 `.gitignore` 排除：

```text
config.json             本机设置
credentials.json        邮箱凭据
state.json              运行状态
persona.md              本机人格
local-style.json        本机表达规则
data/                   探索、手机摘要与会话交接等数据
logs/                   运行日志
```

提交 Issue 时请先移除账号、邮箱授权码、Cookie、私人聊天和健康数据。备份这些目录时也请按个人数据处理。

<a id="diagnostics"></a>

## 命令行与排障

在插件安装目录运行，Node.js 需满足 [package.json](https://github.com/yuyu654/dsh-drop-by/blob/main/package.json) 的版本要求：

```bash
node src/run.js --status     # 查看当前状态
node src/run.js --once       # 执行一拍；是否真发由当前配置决定
node src/run.js --why        # 查看命中或跳过原因
node src/run.js --windows    # 查看配置的运行时段
node src/run.js --persona    # 检查人格来源与内容
node src/run.js --compose    # 查看内容生成结果
node src/run.js --mail       # 查看邮箱状态与已缓存摘要，不主动收取
node src/run.js --mail-now   # 手动强制收取一次，绕过邮箱开关与定时限制
npm test                    # 运行插件测试
```

日常优先使用「陪伴」设置页。完整配置字段可参考 [config.example.json](https://github.com/yuyu654/dsh-drop-by/blob/main/config.example.json)，运行日志位于插件目录 `logs/`。

升级前建议备份本机配置与需要保留的数据。升级后检查依赖检测、聊天绑定和实际发送开关；手机 APK 升级后如果无障碍或截图失效，重新授权再测试。
